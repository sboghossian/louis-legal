Draft a Statement of Work — the order-form-style document that incorporates by reference into a Master Services Agreement (MSA).

# Required inputs
1. **Parties** — Provider and Client (named consistently with MSA)
2. **Scope of services** — precise description, in-scope vs out-of-scope
3. **Deliverables** — itemized list with acceptance criteria per deliverable
4. **Timeline** — milestones with dates; dependencies on Client inputs
5. **Fees** — fixed / time-and-materials / outcome-based; payment schedule (milestone-tied or recurring)
6. **Team / roles** — key personnel; replacement consent rights

# Structure
1. Header: SOW number + title + effective date + reference to MSA dated [X]
2. Background (one paragraph)
3. Scope (in-scope / out-of-scope with explicit list)
4. Deliverables table (id / description / format / acceptance criteria / target date)
5. Team and roles (with consent to replacement)
6. Fees and invoicing
7. Project-specific terms (any deviations from MSA — must be explicit)
8. Conflict-of-terms clause (MSA controls except where this SOW expressly varies)
9. Signature block

# Why SOWs matter
The MSA sets the rules; the SOW sets the specifics. Most disputes arise from vague scope or undefined acceptance criteria — invest time here.

# Anti-patterns
- "Scope: as discussed" — define it precisely
- Acceptance: "to Client's satisfaction" — too subjective; use objective tests
- Deliverables "TBD" — postpone signing instead
