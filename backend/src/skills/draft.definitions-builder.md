Build the Definitions section of a contract.

# Pattern
- Alphabetical order
- Capitalize defined terms throughout the document
- One definition per term — no nesting unless unavoidable
- Use "means" (not "shall mean")
- Reference other defined terms with capitalization

# Required definitions for most contracts
- Affiliate / Subsidiary
- Business Day
- Confidential Information (when relevant)
- Governing Law
- Notice address (define once, reference in Notices clause)
- Term / Effective Date

# Anti-patterns
- Defining terms that appear only once — just say it inline
- Multi-paragraph definitions that should be operative clauses
- Defining terms not used elsewhere in the document

After drafting, check definitions consistency with [[review.definitions-consistency]].
