# `claude-for-legal` skill merge — plan

**Goal.** Absorb every skill from Anthropic's `claude-for-legal` open
collection into Louis's skill registry so the router can pick from the
exhaustive union of (Louis-authored ∪ claude-for-legal) skills. Group
the resulting ~1500 skills under the 10 practice-area playbooks defined
in [`playbooks/`](./playbooks/README.md). Apply bronze / silver / gold
tiering so the router prefers gold first.

**Status.** Plan only. No skills imported yet (decision logged
2026-05-13). Track progress here.

---

## Inputs

- **Upstream repo:** `https://github.com/anthropics/claude-for-legal`
  (verify exact URL when starting; the project may live under a
  different name — e.g. `claude-legal-skills`, `legal-agent-skills`).
- **Local target:** `backend/src/skills/`
- **Manifest:** `backend/src/skills/_REGISTRY.json` (regenerated by
  `_build-registry.ts` after import).
- **Existing skill count:** ~991 (`ls backend/src/skills | wc -l`).

## Stages

### Stage 1 — survey + mapping

1. Clone `claude-for-legal` into `/tmp/cfl-survey`.
2. Walk `cfl/skills/` (or wherever the skill files live).
3. For each upstream skill, capture: `name`, `description`,
   `practice_area` (if present), `jurisdictions`, `intent`,
   raw file path.
4. Produce `IMPORT_MAPPING.csv` with columns:
   `upstream_path | louis_slug | practice_area | tier | conflict_with_existing | action (import / skip / merge)`.
5. Hand-review the CSV. Conflicts to expect:
   - Same name, different content → import as `cfl.<orig-name>` and
     leave Louis's own at `<orig-name>`.
   - Same name, similar content → import as `cfl.` + flag for manual
     diff before deduping.

### Stage 2 — practice-area assignment

Use a small classifier pass (Claude or Gemini) prompted with the 10
playbook descriptions in [`playbooks/`](./playbooks/) to assign every
upstream skill to one practice area. Sanity-check by spot-checking 20
random assignments.

### Stage 3 — tiering

Tier each imported skill:

- **Gold** — referenced by a Louis playbook's standard operating
  sequence; demonstrably high quality.
- **Silver** — useful, well-written, not on the critical path.
- **Bronze** — niche / draft / community-contributed.

Tier surfaces in the router with weights gold > silver > bronze when
selecting the 8–13 skills per turn.

### Stage 4 — import + re-build registry

```sh
node backend/src/skills/_import-from-inventory.ts \
  --source /tmp/cfl-survey \
  --mapping ./IMPORT_MAPPING.csv

npx tsx backend/src/skills/_build-registry.ts
```

`_import-from-inventory.ts` already exists — confirm it handles the
new `cfl.` namespace and tier field, then run.

### Stage 5 — playbook routing

Update the router (`backend/src/skills/_router.ts`) so each turn:

1. Detects the active practice area from matter tag or LLM classifier
   (per decision #21 — LLM classifier picks the model + practice area).
2. Loads the matching playbook from `playbooks/<slug>.CLAUDE.md` as the
   high-level system prompt.
3. Filters candidate skills to `practice_area = <slug>` and assembles
   the top 8–13 by tier × intent × jurisdiction overlap.

### Stage 6 — QA

- Run the existing skill smoke tests.
- Manual: 5 prompts per practice area, confirm router fires sensible
  skills.
- Manual: 3 cross-jurisdictional prompts to confirm fallback chain.
